# ScaleQueue v0.1.0 — Durable jobs and leased workers

Release target: `0641d487d61971aa2d45a184d3029bd02082c51e` (merged PR #1).
This file is prepared release text; its presence does not mean a GitHub release has been published.

## Highlights

- Durable MySQL job acceptance and outbox dispatch; Redis availability is not required for acceptance.
- Client-scoped enqueue idempotency and conflict detection.
- Atomic worker claims, renewable leases, and fenced outcome writes.
- Persistent retry schedules, bounded jittered backoff, and durable DEAD-job handling.
- Periodic pending-delivery recovery and generation-protected manual replay.
- Cooperative bounded shutdown, worker metrics, and authenticated job/audit/replay APIs.
- Docker Compose setup, migrations, demo key seeding, regression tests, and reliability CI.

## Start the released version

After publishing the tag, with Docker Engine and Compose v2 installed:

```bash
git clone --branch v0.1.0 https://github.com/amanshr72/scalequeue.git
cd scalequeue
cp .env.example .env
docker compose up -d --build
curl http://127.0.0.1:3000/health
curl http://127.0.0.1:9090/ready
```

Use the README's enqueue example with the configured demo API key. The built-in
handlers simulate work and send no real emails, notifications, or payments.

## Compatibility and limits

This is an initial demonstrator release, not a stable production API commitment.
Delivery is at least once; external effects require downstream idempotency.
Priority is metadata, not a strict scheduling guarantee. Upgrade older installations
with stopped workers and backed-up stores as documented in `docs/reliability.md`.
